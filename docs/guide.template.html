01 / The problem

You are estimating two things
that depend on each other.

To place a landmark on a map, the robot needs to know where it is. To use that landmark to locate itself, it needs to know where the landmark is. SLAM keeps both estimates—and their shared uncertainty—together.

SLAM · this project

Start with no landmark coordinates. Estimate robot pose and landmark positions jointly.

“Where am I, and what is around me?”
A simple example. You walk through a room with your eyes closed, counting steps. Your position becomes uncertain. Recognizing a previously seen chair gives you a reference again. Your robot does something related using noisy wheel travel and repeated landmark observations.

What is actually known?

The starting pose, wheel separation, assumed noise levels, and landmark IDs when observed. An ID identifies an object; it does not reveal its coordinates.

What is estimated?

The robot’s x, y and heading, each landmark’s x and y, and a covariance matrix describing how uncertain and correlated those estimates are.

Scope matters. This is a landmark-based SLAM project with synthetic range–bearing observations. It does not perform camera recognition, LiDAR feature extraction, occupancy-grid mapping, or unknown data association.

03 / What is in the filter?

The state is an estimate.
The covariance is its uncertainty.

Think of the state as the filter’s current answer, and covariance as a structured description of how much that answer might be wrong.

X = [x, y, θ, m₁x, m₁y, …, mₙx, mₙy]ᵀ State size = 3 + 2N → 23 when N = 10

Why the heading matters

A small orientation error rotates the directions of later observations. Even accurate range measurements can be placed in the wrong part of the map if the robot’s heading is wrong.

Why correlations matter

Two landmarks observed from the same uncertain robot pose share some error. The filter must preserve that connection. A later observation can then improve the robot and correlated landmark estimates together.

Actual final covariance · baseline, seed 7

Hover or tap a cell to inspect a pair of states.

Shown as correlation Pᵢⱼ / √(PᵢᵢPⱼⱼ), from −1 (orange) to +1 (green). Diagonal entries are +1. This normalizes mixed metres/radians for display; the filter itself uses covariance.

An ellipse is not a wall. A covariance ellipse visualizes a Gaussian approximation to uncertainty. Larger means less certain. The report’s landmark ellipses use a 95% two-dimensional Gaussian contour; that does not prove 95% empirical coverage in nonlinear SLAM.
04 / Prediction

Two wheels turn motion
into a pose prediction.

A differential-drive robot steers by changing left and right wheel travel. Try equal values, then move one wheel farther. This is a single-step teaching illustration, not recorded experiment data.

One wheel-travel step

Teaching illustration

Wheel separation b = 0.4 m. Positive = forward, negative = backward. In-place turning occurs when the wheels travel equally in opposite directions.

The project uses a midpoint approximation: it moves along the heading halfway through the turn. The orange dashed path shows substeps to make the intended turn visible; the blue endpoint uses the project’s single midpoint step. Large teaching inputs can make the approximation difference noticeable.

d = (dL + dR) / 2 Δθ = (dR − dL) / b a = θ + Δθ / 2 x′ = x + d cos(a) y′ = y + d sin(a) θ′ = wrap(θ + Δθ)

The filter uses noisy wheel increments. It also propagates their uncertainty into pose uncertainty. Repeated integration without landmark corrections is the odometry-only baseline.

05 / Measurement

A landmark gives a distance
and a relative direction.

Move a landmark and rotate the robot’s heading below. Its range stays unchanged when only the robot’s heading changes, but its bearing changes.

Range–bearing geometry

Teaching illustration

Robot position is fixed at (2, 2) m. The arc marks bearing relative to heading. At zero range, bearing is undefined; the real filter guards against this geometry.

dx = mₓ − x dy = mᵧ − y range = √(dx² + dy²) bearing = wrap(atan2(dy, dx) − θ)

Known ID ≠ known location

“ID 4” means this is the same post as before. Its x/y location is still estimated. This project deliberately separates mapping from the harder problem of recognizing which object was seen.

Why wrap angles?

+179° and −179° point almost the same way. Their shortest difference is 2°, not 358°. Wrapping keeps the bearing innovation inside [−π, π).

How the Gazebo sensor works. The adapter reads simulator poses, calculates ideal range/bearing, adds noise, and supplies ID/range/bearing to the EKF. The EKF never receives the true landmark coordinates. Visibility is 360° within 4.5 m, without occlusion.

First observation is special. Initialization adds a new landmark and its correlations. It does not independently correct the robot’s mean. The code does not immediately reuse the same observation for a correction, because that would double-count it.

Understand the Kalman gain with a one-dimensional analogy

A prior estimate says position 4 m; a measurement says 5 m. How much should the answer move? Change the variances. This scalar example teaches weighting; it is not the nonlinear joint SLAM update.

Larger K pulls the result closer to the measurement. A noisy measurement gets less weight. Variance is squared uncertainty, so smaller means more confidence.

07 / The real equations

Open the mathematics
when the pictures make sense.

The EKF uses local first-order derivatives called Jacobians to propagate a Gaussian approximation through nonlinear motion and sensing.

Why an Extended Kalman Filter?

An ordinary Kalman filter assumes linear state and measurement models. Here, heading enters motion through sine/cosine, and measurements use square root and atan2. The EKF evaluates these nonlinear models and uses their local Jacobians for covariance propagation.

“Extended” does not mean universally more accurate. Large errors can make its local linear approximation unreliable, which is one reason the dropout experiment can leave a distorted map.

Prediction: how G, V, F and Qw work
G = [[1, 0, −d sin(a)], [0, 1, d cos(a)], [0, 0, 1]] V = [[cos(a)/2 + d sin(a)/(2b), cos(a)/2 − d sin(a)/(2b)], [sin(a)/2 − d cos(a)/(2b), sin(a)/2 + d cos(a)/(2b)], [−1/b, 1/b]] F = identity over the full state, with G in its robot block P⁻ = F P⁺ Fᵀ P⁻[robot,robot] += V Qw Vᵀ Qw = diag(σwheel², σwheel²)

G is the derivative with respect to robot pose. V is the derivative with respect to left/right wheel travel. F updates robot/map cross-correlations too. Only the robot block gets new wheel uncertainty, because the landmarks are stationary.

σwheel is in metres per sample, not metres per second. Changing the simulation time step without revisiting the noise model changes the experiment.

Measurement Jacobian H
q = dx² + dy² r = √q Hrobot = [[−dx/r, −dy/r, 0], [ dy/q, −dx/q, −1]] Hlandmark = [[ dx/r, dy/r], [−dy/q, dx/q]]

The full H has two rows and one column per state element. Only the robot and observed landmark columns are nonzero. A change to any other landmark does not directly change this observation prediction, although covariance correlations allow indirect corrections.

New landmark: inverse model and correlated augmentation
α = θ + bearing mnew = [x + r cos(α), y + r sin(α)]ᵀ Arobot = [[1, 0, −r sin(α)], [0, 1, r cos(α)]] B = [[cos(α), −r sin(α)], [sin(α), r cos(α)]] A = [Arobot | zeros for the existing landmark columns] Pnew = [[P, P Aᵀ], [A P, A P Aᵀ + B R Bᵀ]]

A transfers existing state uncertainty into the new landmark. B transfers measurement uncertainty. The off-diagonal blocks retain shared error. This is more than attaching an independent x/y point to the map.

Correction: innovation, gain and Joseph update
ν = z − h(X⁻) wrap the bearing residual S = H P⁻ Hᵀ + R K = P⁻ Hᵀ S⁻¹ X⁺ = X⁻ + K ν wrap the corrected heading P⁺ = (I − KH) P⁻ (I − KH)ᵀ + K R Kᵀ

The innovation ν compares the actual noisy measurement to the expected measurement. S models innovation uncertainty. K maps that discrepancy into a state correction. The Joseph form helps preserve covariance numerically.

The code uses np.linalg.solve rather than explicitly constructing S⁻¹. It symmetrizes P after updates. Observations are processed sequentially and relinearized after each correction.

NIS: a diagnostic, not a proof
NIS = νᵀ S⁻¹ ν

With a well-modeled two-component Gaussian innovation, a mean near 2 is a useful reference. It does not prove full EKF-SLAM consistency: nonlinearization, correlations and finite samples complicate interpretation.

In this project, uniformly underestimating all noise standard deviations leaves trajectory RMSE nearly unchanged while increasing mean NIS from about 2.02 to 16.50. A visually good estimate can still have unrealistic confidence.

Four errors people mix up

Current position error: distance between estimated and true position at one time.

Trajectory RMSE: square root of average squared position error throughout the run.

Final position error: just the last position error.

Map RMSE: landmark-coordinate error, averaged over the discovered map.

What the experiments reveal

Dropout: later robot-position recovery can coexist with a distorted map.

No reuse: without any repeated-landmark corrections, robot trajectory matches odometry exactly. This removes all repeats, not only final loop closure.

Uniform noise underestimation: nearly the same mean estimate, but much less realistic uncertainty.

About the error bars. They show sample standard deviation across per-run RMSE values. They are not confidence intervals. The seed-7 plots are illustrative single trials, not the mean result. The truth and prediction models match in the kinematic simulator, making it more idealized than hardware.

Troubleshooting: the simulator does not open

Run the launcher inside devbox, from the project directory. Gazebo Classic needs gzserver/gzclient, not gz sim. The launcher applies QT_QPA_PLATFORM=xcb to Gazebo/RViz to avoid OGRE window-handle errors with native Wayland.

Inspect results/gazebo/server.log, client.log, and rviz.log. Stop an old run before restarting. The default ROS domain is 74 and Gazebo master port is 11355; two simultaneous launchers need separate values.

Troubleshooting: is loop closure working in the offline replay?

Click Next loop closure in the replay. The first baseline event is at 42.1 s, when landmark 0 returns after more than 10 seconds without an observation. Its original ID and map entry are reused, and the scan changes the estimated robot position by about 0.24 m. Purple rings mark these returning IDs; the correction counter includes every repeated update.

The baseline finishes 0.032 m from the true robot position. The simulation stops at 105 s, just past two complete laps (104.72 s). An EKF corrects the current pose and correlated map; the historical trajectory still shows the estimates made at the time. The no-landmark-reuse scenario deliberately disables all repeated corrections and cannot close a loop.

Troubleshooting: it moves but I cannot see detections

Look at RViz, not only Gazebo. The fixed frame should be map. The MarkerArray topic is /slam_demo/estimated_landmarks. Terminal messages show visible IDs and map/update counts. Empty visible IDs can mean that no landmark is currently within sensor range; previously mapped landmarks remain stored.

The sensor is synthetic. It does not recognize image objects or publish a real LiDAR scan. The first observations initialize landmarks; corrections increase only when mapped landmarks are reobserved.

Troubleshooting: it stops after about two loops

If the last argument was 105 and the terminal printed final metrics at 105 s, the run completed as requested. Use 300 for longer, or 0 until Ctrl+C. A separate safety stop can halt the robot near a post even while simulation time continues.

The node handles signals before ROS context shutdown so it can stop the robot and save results once.

A compact glossary

Pose
Position and orientation: x, y, heading in this 2D project.
Odometry
Motion estimated by integrating wheel travel; errors accumulate.
Landmark
A stationary reference point whose location is estimated.
State
The vector of robot pose and all mapped landmark coordinates.
Covariance P
Variances and shared error relationships between state elements.
Jacobian
Matrix of local derivatives used to linearize a nonlinear function.
Innovation ν
Observed measurement minus predicted measurement.
Kalman gain K
Maps innovation into corrections of the state estimate.
Process noise Qw
Uncertainty in the wheel-travel inputs in this implementation.
Measurement noise R
Uncertainty in range and bearing measurements.
Loop closure
Revisiting and recognizing a previously mapped part of the environment.
Consistency
Whether the filter’s reported uncertainty realistically describes its errors.
